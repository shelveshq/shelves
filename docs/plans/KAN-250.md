# Plan: KAN-250 — Extract translator/resolution.py and translator/panel.py

**Phase:** 1 (refactoring — no new DSL surface area)
**Jira:** KAN-250
**Depends on:** KAN-232 (shared axis hiding), KAN-112 (stacked layers)

## Overview

`stacked.py` and `layers.py` share ~40% of their encoding logic via copy-paste. This ticket extracts the duplicated code into two new shared modules: `translator/resolution.py` (cascade helpers) and `translator/panel.py` (panel encoding builder). After this refactoring, `stacked.py` and `layers.py` become thin orchestrators that call shared helpers, eliminating ~200 LOC of duplication.

This is a **pure refactoring** — no DSL changes, no new features, no schema changes. All existing tests must continue to pass with identical output.

## Test Fixtures & Expected Outputs

Since this is a pure refactoring, there are **no new test fixtures**. The acceptance criterion is:

1. All existing tests pass unchanged — same assertions, same expected outputs.

3. The new modules (`resolution.py`, `panel.py`) are covered by the existing tests transitively — every code path through the new helpers is already exercised by `test_stacked.py` and `test_layers.py`.

```python
from shelves.translator.resolution import resolve_mark
from shelves.translator.panel import build_panel_encoding

def _compile_concat(...) -> VegaLiteSpec:
    is_hconcat = concat_key == "hconcat"
    panels = []
    for i, (entry, mark) in enumerate(zip(entries, effective_marks)):
        # Build encoding via shared helper
        panel_encoding = build_panel_encoding(
            entry=entry,
            shared_enc=shared_enc,
            shared_field=shared_field,
            shared_axis=shared_axis,
            measure_axis=measure_axis,
            spec=spec,
            resolver=resolver,
        )

        # Suppress shared axis on non-edge panels (KAN-232)
        if not _resolve_shared_axis(entries, i, is_hconcat):
            _suppress_shared_axis(panel_encoding, shared_axis)

        panel: VegaLiteSpec = {
            "mark": build_mark(mark),
            "encoding": panel_encoding,
        }

        if transforms:
            panel["transform"] = transforms

        panels.append(panel)

    return {concat_key: panels, "spacing": 10}
```

## Inheritance Resolution

The cascade functions move to `resolution.py` but their logic is **identical** to the current implementations:

```python
# resolution.py

def resolve_mark(layer_mark, entry_mark, top_level_mark, measure_name):
    # Priority: layer > entry > top-level. Raises if all None.
    if layer_mark is not None: return layer_mark
    if entry_mark is not None: return entry_mark
    if top_level_mark is not None: return top_level_mark
    raise ValueError(f"No mark defined for measure '{measure_name}'")

def resolve_property(layer_value, entry_value, top_level_value):
    # Priority: layer > entry > top-level. Returns None if all None.
    if layer_value is not None: return layer_value
    if entry_value is not None: return entry_value
    return top_level_value
```

**Key migration detail for stacked.py:** The old `_resolve_mark(entry, default_mark)` is a 2-level version. It maps to `resolve_mark(None, entry.mark, default_mark, entry.measure)` — the layer argument is always None in the stacked (non-layered) path.

### Patterns to follow

- `resolution.py` follows the same pattern as `encodings.py` — pure functions, no class, no state.
- `panel.py` follows the same pattern as `encodings.py` — builds encoding dicts from inputs.
- Both new modules import from `shelves.schema.chart_schema` and `shelves.translator.encodings`.

### Gotchas

- **stacked.py's `_resolve_mark` has a different signature** (2 args) vs layers.py's (4 args). The unified version uses the 4-arg signature. Stacked callers pass `None` for `layer_mark`.
- **stacked.py's `_compile_concat` uses inline size logic** (`isinstance(size, (int, float))` → `{"value": size}` else `{"field": size, ...}`). This should use `build_size` from `encodings.py` instead — layers.py already does this. The `build_panel_encoding` function uses `build_size`.
- **`_resolve_shared_axis` and `_suppress_shared_axis` stay in stacked.py** — they are imported by layers.py via `from shelves.translator.patterns.stacked import _resolve_shared_axis, _suppress_shared_axis`. Moving them would expand scope. They could move in a future cleanup but are NOT part of this ticket.
- **`_resolve_layer_detail` stays in layers.py** — it has explicit-null semantics via `model_fields_set` that are layer-specific and not shared with stacked.py.
- **`_apply_opacity_to_mark` stays in layers.py** — stacked.py's `_compile_concat` currently doesn't handle entry opacity on non-layered panels, and layers.py does. This is an existing behavioral difference. `build_panel_encoding` does NOT handle opacity — the caller (layers.py's `_build_simple_panel`) applies it after.

### What NOT to change

- Do not move `_resolve_shared_axis` or `_suppress_shared_axis` out of stacked.py.
- Do not refactor `_build_layer_spec` or `compile_layer_entry` — these are layer-specific and not duplicated.
- Do not change the `compile_stacked` or `compile_stacked_with_layers` dispatcher logic.
- Do not change the repeat path in `_compile_repeat` — it has its own encoding logic that doesn't overlap with the concat path.
