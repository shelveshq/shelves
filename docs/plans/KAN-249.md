# Plan: KAN-249 — Split studio/server.py god module into focused sub-modules

**Phase:** Refactor (Tier 1, Item #2 from `docs/plans/refactor_plan.md`)
**Jira:** KAN-249
**Depends on:** KAN-248 (pipeline extraction — merged)

## Overview

`studio/server.py` is a 797-LOC god module bundling seven distinct concerns: `ConnectionManager` (WebSocket broadcast), lifespan/watcher wiring, chart + dashboard compilation pipelines, HTTP route handlers, PTY terminal WebSocket handler, file-tree helpers, and a component-tree visualizer. This makes it impossible to test any concern in isolation and causes every new route to bloat the same file.

This ticket splits the module into focused sub-modules while preserving all existing behavior — no new features, no new endpoints, no changed APIs. KAN-248 already extracted the core pipeline into `shelves/pipeline.py`, so server.py's compilation logic now calls that module. The remaining work is structural: move code into its natural homes within a `routes/` package and top-level studio modules.

After this refactor, `server.py` shrinks to a thin ~80-LOC app factory that imports from the new modules.

## Implementation Notes

### Order of implementation

This refactor must be done in a specific order to avoid broken intermediate states:

1. **Create `connection.py`** — move `ConnectionManager`. Update the import in `server.py` to `from shelves.studio.connection import ConnectionManager`. Run tests.

2. **Create `routes/` package** — create `routes/__init__.py` (empty).

3. **Create `routes/files.py`** — move `_resolve_safe`, `_build_tree`, `_TREE_EXTENSIONS`, `_get_project`, `_get_file`, `_put_file`. Update `server.py` routes to call `files.get_project`, etc. Run tests.

4. **Create `routes/compile.py`** — move `_compile_yaml`, `_get_schema`. Update `server.py` routes. Run tests.

5. **Create `routes/dashboard.py`** — move `_compile_dashboard_yaml`, `_run_dashboard_pipeline`, `_build_component_tree`. Update `server.py` routes. Run tests.

6. **Create `routes/terminal.py`** — move `_is_allowed_ws_origin`, `_ALLOWED_WS_HOSTS`, `_TERMINAL_AUTH_TIMEOUT_SECONDS`, and the `ws_terminal` handler. Update `server.py`. Run tests.

7. **Create `lifespan.py`** — move `_make_lifespan`, `_compile_file_and_broadcast`, `_compile_dashboard_file_and_broadcast`. Update `server.py`. Run tests.

8. **Clean up `server.py`** — remove all moved code, leaving only `create_app` and the inline `index` + `ws_endpoint` handlers. Verify final LOC is ~80. Run full test suite.

### Patterns to follow

- **Route handlers access config via `request.app.state`** — this pattern is already established in the codebase and must be preserved. Route handlers do NOT receive config as function parameters; they read from `request.app.state.project_dir`, `request.app.state.theme_path`, etc.

- **WebSocket handlers access config via `ws.app.state`** — same pattern for WebSocket endpoints.

- **Lazy imports inside functions** — several route handlers use `import yaml as _yaml` and `from shelves.pipeline import compile_chart` at function scope. Preserve these lazy imports; don't hoist them to module level. This keeps import time fast and avoids circular imports.

- **The `ws_endpoint` (live-reload WS) stays inline in `server.py`** — it's only 7 lines and tightly coupled to the ConnectionManager instance. Not worth a separate module.

- **The `index` handler stays inline in `server.py`** — it reads the static HTML and injects the terminal token meta tag. It's 4 lines and specific to the app factory.

### Gotchas

- **`_compile_dashboard_file_and_broadcast` calls `_run_dashboard_pipeline`**: After the split, `lifespan.py` needs to import `run_dashboard_pipeline` from `routes/dashboard.py`. This creates a dependency: `lifespan.py` → `routes/dashboard.py`. This is fine — it's a one-way dependency with no cycle.

- **`_STATIC_DIR`** stays in `server.py` — it's used by the static mount and the index handler, both of which remain in the app factory.

- **Don't change the leading-underscore convention inconsistently.** The route handler functions currently have leading underscores (e.g. `_compile_yaml`). When moving to separate modules, drop the underscore since they become the module's public API. But helper functions within each module (like `_build_tree` called only by `get_project`) keep the underscore.

### What NOT to change

- Do NOT refactor the exception handling (the 19 `except Exception` blocks). That is a separate concern tracked separately.
- Do NOT change any route paths, HTTP methods, or response shapes.
- Do NOT modify `cli.py`, `watcher.py`, or `terminal.py`.
- Do NOT modify any test files — the existing tests are the acceptance criteria.

## Out of Scope

- **Exception handling cleanup** — the 19 `except Exception` blocks stay as-is. Replacing them with specific catches (`ValidationError`, `YAMLError`) is a separate ticket per `refactor_plan.md`.
- **Router-based route registration** — FastAPI's `APIRouter` could replace the inline route definitions, but that's an architectural change beyond this ticket's scope.
- **Dashboard pipeline extraction** — `_run_dashboard_pipeline` could move to `shelves/pipeline.py` alongside `compile_chart`. That's a follow-up to KAN-248, not part of this split.
- **Test file restructuring** — `test_studio_cli.py` stays as one file. Splitting tests to match the new module structure is optional future work.
